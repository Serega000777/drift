# Политика безопасности

## Сообщить об уязвимости
Не создавайте публичный issue. Напишите владельцу репозитория приватно (GitHub → Security → Report a vulnerability, если включено, или личным сообщением). Укажите шаги воспроизведения, затронутую версию/коммит и возможный вред. Мы подтвердим получение в течение 3 рабочих дней.

## Что считается уязвимостью
- Утечка токенов/ключей, обход подписи сохранений в онлайн-функциях, чтение чужих данных.
- Выполнение кода через загружаемый контент (модели, раскладки, призраки, сохранения).
- Обход возрастных ограничений и согласий.

## Правила для разработчиков и ИИ-агентов
1. **Никаких секретов в репозитории.** Ключи API, пароли, keystore — только в переменных окружения / секретах CI / менеджере секретов. Перед коммитом работает `tools/security/scan-secrets.sh` (включить: `tools/setup/install-hooks.sh` или `.ps1`), в CI — то же сканирование.
2. Если секрет попал в историю: **сразу отозвать/перевыпустить**, затем чистить историю — удаление файла не помогает.
3. Клиент игры **не доверенная среда**: всё соревновательное (кошелёк онлайн, рекорды, турниры) проверяет сервер. Подпись сохранений — только защита от «случайной» правки.
4. Пользовательский контент (раскладки, призраки, манифесты моделей) — только данные; парсер с лимитами размера/глубины, санитизация, никаких скриптов и AssetBundle от игроков.
5. Логи — только через `SafeLog` (маскирует токены, почту, пути пользователя).
6. Релизная сборка — меню **Drift Career → 4. Release Hardening** (IL2CPP, stripping, без dev-флагов, проверка секретов).
7. Репозиторий держать **приватным**, включить 2FA, защиту ветки `main`, GitHub secret scanning и push protection.

Подробно: `docs/SECURITY_PRIVACY.md`, API сервера: `docs/BACKEND_API.md`.
