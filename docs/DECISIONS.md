# Решения (ADR, кратко)

**D-001. Чистое ядро без UnityEngine.** Физика, правила, данные и сохранения в `DriftCareer.Core` (`noEngineReferences`). Причина: тестируемость (`dotnet test` в CI без лицензии Unity), детерминированность, переиспользование на сервере для античита. Цена: свой `Vec2`, свой JSON.

**D-002. Лучевые колёса + свой решатель вместо WheelCollider.** WheelCollider не даёт контроля над моделью шины и трансмиссией. Свой решатель последовательных импульсов стабилен для сварки/сцепления/тормозов на шаге 0.01.

**D-003. Шаг физики 0.01 с, 2 подшага трансмиссии.** Компромисс точность/цена на мобилках; оценить 0.02 на слабых устройствах после замеров.

**D-004. Угол заноса — в центре задней оси.** Иначе кинематический увод ЦМ в тугих поворотах считается дрифтом.

**D-005. Авто-КПП по скорости земли.** Держит передачу в заносе (как делают дрифтеры) и не даёт каскада переключений от пробуксовки.

**D-006. Свой минимальный JSON и явные кодеки.** Одинаковое поведение в Unity (Mono/IL2CPP) и dotnet, без рефлексии и полиморфной десериализации (безопасность), лёгкие миграции. Конверт с CRC.

**D-007. UI Toolkit, экраны собираются кодом + USS.** Текстовые, диффабельные, удобные для ИИ; масштабирование под любые экраны (ScaleWithScreenSize); USS-переходы для анимаций; своя навигация фокусом для геймпадов/консолей.

**D-008. Процедурный контент на старте.** Никаких сторонних ассетов → нет лицензионных рисков; лёгкий проект для Mac M2 8 ГБ. Замена на CC0/лицензированные модели — позже, с записью в ASSET_LICENSES.

**D-009. Одна бесшовная сцена.** Академия — фон меню и гаража; переходы без загрузок. Новые трассы — через `loaderId` (scene/addressable).

**D-010. Своя камера вместо Cinemachine.** Меньше зависимостей, точный контроль дрифт-камеры и коллизий.

**D-011. Реальные бренды только как справочные данные.** Названия марок/моторов/трасс — в `referenceNote`/`referenceCode`, в UI — обобщённые названия; показ кодов только с `DC_SHOW_REFERENCE_NAMES`. До лицензии — `RequiresLicense` и «Скоро».

**D-012. Мягкая валюта только за игру, без pay-to-win.** Платная — позже, привязана к магазину платформы.

**D-013. Кросс-прогрессия: сервер авторитетен, детерминированный merge.** Заработанное общее, платное — по правилам платформ; политики платформ в данных (`PlatformPolicy`).

**D-014. Онлайн: сначала тандем с призраком, затем сеть.** Позволяет выпустить парные заезды без сервера и использовать те же записи для античита.

**D-015. Своя 3D-модель — только визуал.** Физика из паспорта (`VehicleSpecSheet`); модель не влияет на динамику. Импорт в редакторе (ПК); публично — через модерацию и доверенную сборку, без AssetBundle игроков.

**D-016. ИИ-распознавание на сервере.** Ключи API не в клиенте; результат — предложения с уверенностью, подтверждает игрок; честная пометка «приближение по спецификациям».

**D-017. Расхождение с ТЗ: «ПК» vs «MacBook».** ТЗ упоминает MacBook M2, владелец тестирует «на ПК». Проект платформонезависим; скрипты установки есть для Windows (ps1) и macOS/Linux (sh).

**D-018. Расширение объёма MVP по запросу владельца.** ТЗ откладывало гараж/режимы; владелец явно попросил тюнинг, валюту, турниры, испытания, тандем — реализованы офлайн-части; всё, что требует сервера, оставлено «Скоро» с готовыми интерфейсами.

**D-019. Подписанные сохранения не стирают прогресс.** Неверная подпись → флаг `integrityCompromised` (липкий) и отключение соревновательного, а не удаление. Причина: подпись может «сломаться» и без злого умысла (перенос на другое устройство, сбой), терять прогресс игрока хуже, чем терпеть читера в офлайне.

**D-020. Гость по умолчанию, вход — по желанию.** Игра полностью доступна без аккаунта; вход платформы нужен только для онлайна и кросс-прогрессии. Клиент не хранит пароли и пропуски платформ; проверяет их только сервер.

**D-021. Короткий access-токен в памяти + ротируемый refresh в зашифрованном хранилище.** Утечка дампа файлов не даёт долгоживущего доступа; повтор refresh-токена на сервере отзывает всю сессию.

**D-022. Конфиденциальность: всё opt-in, неизвестный возраст = ребёнок.** Согласия выключены по умолчанию, дата рождения не хранится (только группа), ограничения применяются в кодеке и в `PrivacyRules.Resolve`, а не только в UI.

**D-023. Процедурный персонаж вместо стороннего.** Нет лицензий и тяжёлых ассетов, экипировка — данные. Свою модель — только через редакторный импорт (ПК), как и для машин (D-015).

**D-024. Загрузка по реальным этапам.** Мир строится корутиной по этапам, прогресс — настоящий, а не таймер; минимальное время показа, чтобы не мигало. «Уменьшить движение» заменяет шторку простым затемнением.

**D-025. Анализаторы и «предупреждения = ошибки» в CI ядра.** Чистый код поддерживается автоматически; Runtime держится на 0 предупреждений при компиляции против reference-сборок.
