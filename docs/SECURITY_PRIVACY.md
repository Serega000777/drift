# Безопасность и конфиденциальность

> Статус: клиентская часть реализована и покрыта тестами (`SecurityTests`, `IdentityAndCharacterTests`). Сервера аккаунтов пока нет — всё, что требует сервера, описано как контракт (`docs/BACKEND_API.md`). Юридические формулировки — черновик, перед релизом их проверяет юрист.

## 1. Модель угроз (кратко)
| Угроза | Где | Защита сейчас | Что нужно на сервере |
|---|---|---|---|
| Правка сохранений (кредиты, рекорды) | профиль на устройстве | HMAC-подпись сохранений, «липкий» флаг `integrityCompromised`, данные не стираются | авторитетный кошелёк и рекорды на сервере |
| Кража токенов входа | устройство, логи, бэкапы | access-токен только в памяти; refresh — в зашифрованном хранилище; маскировка в логах | ротация refresh-токенов с обнаружением повторного использования |
| Подделка входа платформы | запрос входа | клиент передаёт только одноразовый «пропуск» платформы | проверка пропуска у Steam/Google/Apple/PSN/Xbox |
| Вредоносный контент (раскладки, призраки, манифесты) | файлы/импорт | парсер с лимитами глубины/размера, файлы ≤ 8 МБ, санитизация, без скриптов и AssetBundle | модерация и доверенная сборка UGC |
| Обход возрастных ограничений | онбординг | безопасные значения по умолчанию, неизвестный возраст = ребёнок, принудительные ограничения в кодеке | возрастные данные платформы, родительский контроль |
| Утечка персональных данных | логи, UI, ник | `SafeLog`/`LogRedactor`, маскировка ID, правила ника против почты/телефона | минимизация, сроки хранения |
| Утечка ключей разработки | репозиторий | сканер секретов (pre-commit + CI), `.gitignore`, Release Hardening | менеджер секретов, отдельные ключи по окружениям |
| Реверс клиента | сборка | IL2CPP + сильный stripping, без dev-флагов | серверная проверка всего соревновательного |

Клиент игры — недоверенная среда. Подпись сохранений останавливает «правку блокнотом», но не опытного атакующего; поэтому соревновательные функции включаются только с сервером (`Capabilities.competitiveSubmissions`).

## 2. Ключи и хранилище секретов
- `DeviceKeyProvider`: мастер-ключ = HMAC(«перец» сборки, случайный секрет установки + ID устройства + bundle id). Секрет установки хранится в PlayerPrefs (на Android/iOS — приватное хранилище приложения).
- Из мастер-ключа выводятся независимые подключи (`Crypto.DeriveKey`): подпись сохранений, хранилище секретов.
- `EncryptedFileSecureStore`: AES-256-CBC + HMAC-SHA256 (encrypt-then-MAC), имена файлов — HMAC от имени ключа. Хранит refresh-токен, ID аккаунта, ID установки.
- **TODO до релиза:** заменить на Keychain (iOS), Android Keystore, Windows DPAPI/Credential Manager, хранилища консолей — через `ISecureStore`/`IKeyProvider`, без изменения остального кода.

## 3. Авторизация (клиент)
`AuthService` — конечный автомат: `SignedOut → SigningIn → SignedIn ⇄ Refreshing`.
- По умолчанию — **гость**: локальный профиль, ID установки случайный (не из железа).
- Вход через платформу: SDK выдаёт одноразовый пропуск → сервер проверяет его у платформы → выдаёт сессию. Клиент никогда не видит пароль и не хранит пропуск.
- Access-токен живёт минуты и только в памяти; refresh-токен ротируется при каждом обновлении и хранится зашифрованно.
- Обновление заранее (за 2 минуты до истечения), экспоненциальная пауза при ошибках сети (5 → 15 → 45 … до 300 с), отзыв/повторное использование → выход и продолжение игры гостем.
- Выход: уведомление сервера + удаление секретов локально.
- Онлайн-функции проверяют `AuthorizationHeader()` (null без валидной сессии).

## 4. Данные игрока (инвентарь)
| Данные | Где | Зачем | Срок |
|---|---|---|---|
| Настройки | `settings.json` | работа игры | пока установлена игра |
| Профиль: прогресс, тюнинг, кошелёк и история (60 операций), персонаж, ник | `profile.json` (подписан) | прогресс | пока установлена игра / до удаления |
| Согласия и возрастная группа | `privacy.json` (подписан) | законные ограничения | до изменения |
| Раскладки полигона, призраки | `layouts/`, `ghosts/` | функции игры | до удаления |
| Секреты (refresh-токен, ID) | `secure/*.sec` (зашифрованы) | вход | до выхода/удаления |
Не собираем: имя, почту, телефон, контакты, геолокацию, рекламные ID. Дата рождения не хранится — только возрастная группа.

## 5. Права игрока
- **Доступ/переносимость:** «Личный кабинет → Конфиденциальность → Выгрузить мои данные» — JSON со всеми локальными данными (без токенов и ключей).
- **Удаление:** «Удалить все мои данные» (двойное подтверждение) — сохранения, бэкапы, файлы в карантине, раскладки, призраки, выгрузки, секреты и секрет установки; игра перезапускается в первый запуск.
- **Отзыв согласий:** переключатели в том же разделе, действуют сразу.
- С сервером: `DELETE /v1/account` (удаление серверных данных ≤ 30 дней), `GET /v1/account/export`.

## 6. Дети и подростки
- Возраст спрашивается нейтрально (три равные кнопки), без подталкивания.
- До ответа и для младше 13: чат, публикации UGC, импорт моделей, покупки, ник в таблицах, статистика и реклама по интересам — выключены.
- 13–17: без рекламы по интересам и рассылок, без текстового чата.
- Ограничения применяются ещё и в кодеке (`PrivacySettings.Enforce`) — правка файла не включит запрещённое.
- **До релиза:** сверить с COPPA, GDPR-K/UK Age Appropriate Design Code, правилами Google Play Families, App Store Kids, требованиями платформодержателей; учитывать возрастные данные платформы, если она их предоставляет.

## 7. Ник и публичные данные
`PlayerIdentity`: 3–20 символов, буквы/цифры/пробел/_-., без «@» и длинных цифровых последовательностей (почта/телефон), зарезервированные слова (admin, support…). Ник по умолчанию «Drifter-XXXX» не раскрывает ничего. На сервере — дополнительная модерация.

## 8. Логирование
Только `SafeLog`: маскирует JWT, Bearer, `token=/password=/secret=…`, почту, длинные hex/base64, домашние пути пользователя. ID показываются маскированными (`a1b2…9f0e`).
